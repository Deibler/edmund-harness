Logs are filed by subject, rotated, and kept within a size; the data folder has a declared layout.

- **Channels.** Every log line still goes to `data/daemon.log`, unchanged, and is also written as a JSON record to `data/logs/<channel>/<day>.jsonl`: `model`, `tool`, `message`, `cron`, `trigger`, `ghost`, `agent`, `memory`, `call`, `integration`, `security`, `system`, and `error`, which holds a copy of every warning and error from everywhere. A test fails when a log tag in the code has no channel.
- **Recorded for the first time**: every outbound HTTP request a harness process makes (`net-out`), every request a harness server answers (`net-in`, with 401/403/429 copied to `security`), every child process with its exit code and duration and the process tree as the system reports it (`proc`), memory, CPU, GPU, swap, disk and thermal state once a minute (`resource`), what the model opened on the web (`browse`), and the exception that ends a process, with its stack. Query strings, headers and bodies are never recorded.
- **Tracing.** Each record carries its conversation and turn. `edmund logs trace <turn id>` reads one turn back across every channel; `edmund logs trace <name> --at 14:05` reads a conversation around a time. `edmund logs <channel>`, `edmund logs errors`, `edmund logs channels`.
- **Rotation.** `daemon.log` rotates daily into `data/logs/daemon/`; files are compressed after two days and removed after thirty, under a total cap (`[logs]`). The first start files the existing log by day and puts what is older than the retention window in `data/logs/archive/`, which is kept. Under launchd the daemon no longer prints each line to `launchd.out.log` and `launchd.err.log` as well.
- **Flood guard.** A line of one shape repeated more than 200 times in ten seconds is cut off and counted.
- **Fixed: the scheduler stopped the daemon when the clocks went back.** For the repeated hour, a recurring job's next fire was computed as a time already past, and the drain launched one hourly job 7.7 million times: 28 minutes unresponsive and 1.9 GB of one log line (2026-11-01). The arithmetic no longer goes through local time, and a job that is still due after being marked fired is launched once a minute at most.
- **Fixed: the printer link doubled its reconnect loops.** A connection attempt that failed also reported a dropped connection, and each report started another retry loop: 4,290 attempts a minute after an hour with the printer off.
- **Fixed: token counts were hidden in the log.** Any field whose name contained `token` or `key` was replaced with `***`, including `tokens=` counts and the session in `key=`. A field is hidden when it is named like a credential and holds one.
- **`edmund data audit` / `edmund data clean`.** The data folder's contents are declared with their owners (`src/util/data-layout.ts`). The audit lists what a removed feature left behind, hand-made backups, stale undeclared files (empty, or a log, and long untouched) and anything unaccounted for; a clean moves the first three into `data/.trash/` for thirty days and touches nothing else it does not know.
- The weekly review reads the week's log files instead of the whole of `daemon.log`.
